# user-auth 规格(变更增量)

## Purpose

为背单词 APP 提供本地账号体系:用户注册(用户名、密码、头像)与登录,凭据持久化在本地数据库中,登录成功后进入主界面并展示当前用户的用户名与头像。

## ADDED Requirements

### Requirement: 登录界面为应用入口

应用启动后显示的第一个界面 SHALL 为登录界面,未登录用户 MUST NOT 直接进入主界面。

#### Scenario: 冷启动应用

- **WHEN** 用户启动应用
- **THEN** 显示登录界面,包含用户名输入框、密码输入框、头像选择入口、登录按钮与注册入口

### Requirement: 用户注册

系统 SHALL 允许用户注册新账号,注册信息 MUST 包含用户名、密码和头像,且 MUST 持久化到本地数据库。用户名 MUST 唯一;用户名或密码为空、未选择头像、或用户名已存在时 MUST 拒绝注册并提示原因。

#### Scenario: 注册成功

- **WHEN** 用户填写未被占用的用户名、非空密码并选择头像后提交注册
- **THEN** 系统将账号信息写入本地数据库,并提示注册成功

#### Scenario: 用户名已被占用

- **WHEN** 用户使用已存在的用户名提交注册
- **THEN** 系统拒绝注册,并提示用户名已存在

#### Scenario: 必填项缺失

- **WHEN** 用户未填写用户名或密码、或未选择头像就提交注册
- **THEN** 系统拒绝注册,并提示缺少的信息

### Requirement: 用户登录

系统 SHALL 根据本地数据库中的凭据校验登录。校验通过 MUST 进入主界面;校验失败 MUST 留在登录界面并提示错误。

#### Scenario: 登录成功

- **WHEN** 用户输入已注册的用户名和对应密码并点击登录
- **THEN** 系统校验通过,跳转到主界面

#### Scenario: 密码错误

- **WHEN** 用户输入已注册的用户名但密码不匹配
- **THEN** 系统提示用户名或密码错误,停留在登录界面

#### Scenario: 用户名不存在

- **WHEN** 用户输入未注册的用户名
- **THEN** 系统提示用户名或密码错误,停留在登录界面

### Requirement: 用户信息传递与展示

登录成功后,系统 SHALL 将当前用户的用户名与头像传递至主界面,主界面 MUST 显示该用户名与头像。

#### Scenario: 主界面显示当前用户

- **WHEN** 用户登录成功进入主界面
- **THEN** 主界面显示该用户的用户名和注册时选择的头像
